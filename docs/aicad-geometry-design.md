# AiCAD：AI 可編輯 3D／2D 改版規格

狀態：使用者確認維持 AiCAD 名稱並指示繼續；依本規格分階段實作。

## 目標與既有約束

將 AiCAD 的新建主流程改成「選擇 3D 模型／2D 圖紙 → 提示詞及參考檔案 → 對應設定 → 生成 → 手動或 AI 全面／局部修改」。AI 輸出結構化幾何文件，由本機幾何核心建模，2D 使用向量實體；生成圖片不能作為這兩種模式的最終幾何成果。

依據使用者提供的《3D 建模與 2D 工程圖完整設定指南》及《AI 驅動之可編輯 3D 建模與 2D CAD 系統 — 完整設計與開發方案》。保留未要求變更的 Provider 管理、語言、主題、歷程、舊圖面編輯、更新、Windows 單一 EXE、圖示及現有 Go/WebView2 架構。所有 src 檔案維持 CRLF。

## 名稱與相容性

依使用者最新指示，程式維持 AiCAD，執行檔維持 dist-exe\AiCad.exe，目錄維持 D:\Project\aicad，遠端維持 2mf-hermes/AiCAD；取消所有更名工作。

既有資料目錄、WebView2 profile、secretRef、儲存鍵及單例 mutex 保持相容。設定載入完成前禁止寫入預設值。新幾何文件採用明確版本欄位，並與舊圖面資料共存。

## 技術方案與取捨

優先方案：React/TypeScript + Three.js 顯示、Worker 中的 OpenCascade WASM、Replicad 作為幾何 API 封裝。保留 Go host 及現有儲存橋接。實作前以小型實驗驗證 WASM 在 Vite 與封裝 EXE 中載入、布林運算、特徵重算及 STEP 匯出。

替代方案一為直接綁定 OpenCascade.js，控制完整但開發及記憶體管理成本較高；封裝 API 缺少的必要能力才使用此路徑。替代方案二為僅用 Manifold 生成網格，布林較方便，但無法單獨滿足精準 B-Rep 及工程 STEP 目標，因此不作工程模式的唯一核心。

不執行 AI 回傳的 JavaScript 或 Python。只允許經 schema 驗證的 JSON 操作白名單。遠端微服務、資料庫、協作及 GPU 推論是附件的擴充架構，先保留介面；它們是否納入本次必須在審閱時確認，避免破壞現有單 EXE 本機運作模式。

## 文件與操作模型

新增有 schemaVersion 的 EngineeringDocument，包含 documentId、mode、units、settings、parameters、featureTree、drawingSheets、metadata、revision。每個特徵、草圖實體、圖層、註記都有穩定 ID。

參數公式使用受限算式解析器，支援數值、參數引用與算術；檢查循環引用、非有限數字、長度及運算預算。模型尺寸使用明確單位並於核心轉換，不以顯示像素代替工程尺寸。

3D 特徵依賴有向圖涵蓋草圖、拉伸、旋轉、掃掠、布林、孔、圓角、倒角、抽殼、鏡射及陣列。依賴檢查後才執行；刪除、抑制及排序必須保持合法依賴。所有手動與 AI 操作走同一命令層，支援復原、重做及版本快照。

拓撲選取使用來源特徵、草圖來源及幾何描述；不保存易變的面陣列索引作永久 ID。重算後匹配不到或匹配不唯一時回報需重新選取，不能猜測並修改其他面。

2D 實體涵蓋線、圓、圓弧、折線、樣條、填充、文字、尺寸、公差、圖塊及圖層；沿用及擴充現有 CAD 工具。幾何約束需要實際求解及欠／過約束狀態，不能將捕捉功能稱為完整約束求解。

## AI 模型分工與生成

設定提供統一模型及分別設置模型。角色為提示詞精煉、參考圖辨識、3D 建模、2D 建圖及幾何修復／修改。每個角色綁定 Provider 實例與模型；統一模式共用一個選擇，分工模式空值按明確規則回退至統一模型。

保留端點、鑑權、模型清單搜尋、逾時與有限重試。新幾何流程使用文字／多模態端點，不使用影像生成或局部重繪端點。只有配置有效精煉角色時才啟用精煉按鈕；精煉結果可編輯，不隱藏改寫原始需求。

參考附件沿用大小限制與型別驗證。圖片交予具視覺能力的角色；可讀文字、CSV、JSON 以內容及檔名提供上下文。CAD 檔案需對應解析器，無解析能力時顯示原因，不能宣稱已理解檔案。

生成流程：蒐集需求／設定／參考 → AI JSON AST → schema／依賴／預算驗證 → Worker 建模 → 幾何完整性檢查 → 成功後原子提交文件及歷程。失敗時回傳失敗特徵與原因給修復角色，最多三次修復，不先覆蓋使用者可用文件。

全面修改提交當前文件與指令；局部修改提交選取 ID、必要依賴及可修改範圍。局部 patch 驗證不得更動範圍外實體；跨依賴的必要影響先在預覽說明，確認後套用。過期的 AI 回應不得覆蓋更新後文件。

## 設定與介面

維持桌面工程工作區：中央 3D／2D 畫布、左側可折疊特徵樹／圖層、右側參數及文件歷程、底部 AI／CAD 指令列。工具依模式和選取內容顯示，頂部窄視窗橫向滑動，浮層受視窗邊界約束。沿用亮暗主題、五種語言、鍵盤導覽、清楚選取與忙碌狀態。

建立精簡 DESIGN.md 定義工程用字級、間距、色彩、面板密度、焦點與錯誤狀態。不為桌面 CAD 強制引入行動版專用平台或外部設計服務。

3D 設定依附件分組：單位與精度、座標及顯示、草圖約束、製造特徵預設、連續性及核心公差、材料／密度／外觀、組合配合及間隙、組態、自訂屬性、轉檔精度。

2D 設定依附件分組：ISO／JIS／ASME／CNS、投影、紙張／圖框／修訂／比例、視圖與剖面／詳圖、線型與中心線、基準及尺寸方式、公差及 GD&T、表面／孔／焊接註記、BOM、圖層與線寬、輸出。

設定需要連接至實際幾何、註記、驗證或輸出行為。未具備的能力顯示原因與狀態，不放置看似可用的空按鈕。

## 輸出與能力範圍

工程 3D 以核心生成的 B-Rep 匯出 STEP，支援核心實際提供的 IGES；網格格式以實體的三角化結果輸出 STL／OBJ／GLB。2D 匯出 SVG／DXF／向量 PDF，圖層及工程比例必須保留。切割 DXF 為實際 1:1，排除圖框、尺寸及中心線。

3D→2D 使用真正的幾何投影，分離可見、隱藏及中心線；不能用螢幕截圖或無遮蔽處理的邊線投影冒充 HLR。

DWG、Parasolid、FBX 通常需要額外轉換器或授權，須驗證實際可用工具與再散布條件後才提供。不能將 DXF 改副檔名稱為 DWG。

附件涵蓋獨立的自由曲面／雕刻、完整裝配運動、協作及雲端轉換系統。這些範圍需單列實作與驗收，不將工程特徵原型視為附件全部完成；首個發布範圍須由使用者審閱確認。

## 驗收與發布條件

1. 固定幾何範例可建立帶孔支架，修改參數後重算；檢查孔、布林、圓角、抑制與復原重做，不只檢查有顯示三角網格。
2. 2D 圖層、選取、OSNAP、尺寸、修剪／延伸、圖塊、陣列及輸出回歸測試；單位與切割 DXF 比例正確。
3. 模擬 Provider 測試統一／分工角色、三次修復上限、取消、逾時、錯誤 JSON、超量幾何與局部範圍保護。未有實際憑證測試時明確披露。
4. 舊版本文件及設定 fixture 可讀取，舊歷程彼此隔離，新文件保存後重開仍可編輯。
5. Worker WASM、字型及資產在單 EXE 中離線載入；主題、窄視窗、下拉選單、選取及快捷鍵經瀏覽器和封裝視窗檢查。
6. TypeScript、Vitest、適用 Go 測試、正式建置、CRLF 驗證通過。Go 測試先確認不會修改真實使用者資料，使用隔離測試目錄。
7. 套件、lockfile、host、build 與 PE 資源版本一致，建議本次進版 0.4.0。沿用現有圖示與封裝方式。
8. 完成來源 commit／push 後才執行 release 腳本；核對標籤來源、資產版本與校驗碼。停止本次開啟的開發伺服器。

## 建議實作順序

A. 幾何核心與封裝探針、AST、命令及驗證邊界。
B. 模型角色、生成／修復、全域／局部修改、引用附件。
C. 3D 與 2D 工作區、模式設定、特徵及手動編輯。
D. 真正投影、匯出、文件遷移與回歸驗收。
E. 文件更新、單 EXE 驗收與 GitHub 發布。

每一階段保留可測試且可回復的提交。這份規格未宣稱上述功能已完成。
