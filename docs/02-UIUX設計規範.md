# Ai Cad — UI/UX 設計規範

> 原創設計語言。參考 iOS 26/27 世代的**設計原則**（材質分層、內容優先、克制的動效），
> 但不複製任何 Apple 的專有元素、圖示、字體或精確色值。
> 所有 token 定義在 `src/styles/tokens.css`，元件中**禁止寫死色碼**。

---

## 一、設計立場：什麼是「AI 味」，以及怎麼徹底移除

先定義敵人。目前市面上 AI 工具最容易辨識的十個廉價信號：

| # | 常見 AI 工具的做法 | 為什麼廉價 | Ai Cad 的做法 |
| --- | --- | --- | --- |
| 1 | 紫→粉漸層、霓虹光暈 | 已成為「AI 生成」的視覺代名詞 | **全App零漸層裝飾**。唯一強調色是技術藍 `#4c8dff`，只用於「當前選取／主要動作」 |
| 2 | 到處都是 emoji 與 ✨ | 削弱專業感 | 介面內**零 emoji**。所有符號都是自繪的幾何圖示 |
| 3 | 混搭多套圖示庫 | 線寬、端點、視覺重心不一致 | 全部自繪：20×20 網格、1.5px 線寬、圓角端點、`currentColor` 繼承 |
| 4 | 圓角尺寸每處都不同 | 缺乏系統性 | 圓角**只有三檔**：7 / 12 / 18px，各對應一個層級 |
| 5 | 大量彩色標籤與徽章 | 視覺噪音 | 狀態只用 6px 的圓點 + 文字，語意色僅極小面積使用 |
| 6 | 誇張的彈跳／旋轉動畫 | 打斷工作流 | 所有轉場 ≤ 260ms，只有三條曲線，彈簧曲線僅用於「確認」回饋 |
| 7 | 「✨ AI 魔法生成」這類文案 | 遮蔽了實際發生的事 | 文案全部具體：「產生圖面」「重繪選區」「以 Claude 精煉」 |
| 8 | 隱藏 prompt，只給結果 | 使用者無法除錯與重現 | 右欄永久顯示 `resolvedPrompt`，可全選複製 |
| 9 | 假的進度百分比 | 欺騙 | 進度是**具名階段**：「精煉幾何描述」→「繪製圖面」→「合成遮罩」 |
| 10 | 通用置中的空狀態插圖 | 佔位感 | 空狀態直接教下一步操作，配藍圖格線暗示這是製圖工具 |

**核心信念：專業工具的美感來自「克制」與「資訊誠實」，不是來自裝飾。**

## 二、色彩計畫

### 2.1 結構：五層深度

深色為預設（製圖工具長時間使用，深色減少眼疲勞），淺色為**獨立調校**的一組值，不是把深色反轉。

```
--bg-canvas  #101114  ← 畫布井（最深，視覺凹陷）
--bg-base    #17181b  ← 視窗底
--bg-panel   #1f2125  ← 側欄 / 檢視器
--bg-raised  #262a2f  ← 卡片 / 輸入框
--bg-hover   #2e333a  → --bg-active #363c44
```

**要點：畫布比視窗更深。** 這讓畫布看起來是「挖進去的凹槽」而非「浮在上面的紙」，是專業製圖軟體的空間語彙。

底色刻意選**石墨中性色**（帶極微暖），不是藍黑、不是純黑。純黑在 OLED 上會讓 hairline 分隔線消失，藍黑則太像遊戲 UI。

### 2.2 前景：三級文字

```
--fg-primary    #f2f3f5   內容、主要標籤
--fg-secondary  #a3a8b0   欄位標籤、輔助說明
--fg-tertiary   #6c727c   停用、佔位符
```

三級足夠建立層次，第四級只會製造模糊。

### 2.3 強調色：只有一個

```
--accent  #4c8dff  技術藍
```

**整個 App 只有「當前選取」與「主要動作」能用強調色。** 這條紀律讓使用者的眼睛永遠知道該看哪裡。多強調色 = 沒有強調色。

### 2.4 語意色：極小面積

```
--ok      #43c08a   連線成功、就緒
--warn    #e0a94a   未設定引擎
--danger  #f0655f   錯誤
```

僅用於 6px 狀態圓點與單行文字，**絕不用作背景填色**。

### 2.5 圖面語言色

專為製圖語境設計的一組色，需在深淺兩底皆可辨識：

```
--dim-line     #7fd4c1   尺寸標註線（Phase 4 向量疊層）
--mask-stroke  #ffb454   選區邊框（琥珀色，與強調藍完全區隔）
--mask-fill    rgba(255,180,84,0.13)
--grid-minor / --grid-major   藍圖格線
```

**選區用琥珀色而非藍色**，因為選區是一個「待處理的暫時狀態」，語意上必須與「已選取」區隔開。

### 2.6 陰影：只有兩檔，且永遠帶內描邊

```
--shadow-1  0 1px 2px rgba(0,0,0,.4),  inset 0 0 0 1px rgba(255,255,255,.05)
--shadow-2  0 12px 32px -6px rgba(0,0,0,.6), inset 0 0 0 1px rgba(255,255,255,.07)
```

那個 1px 內描邊是關鍵細節：它模擬材質厚度，讓元件看起來是「有實體的板」而非「貼上的色塊」。少了它，介面會立刻扁平廉價。

### 2.7 材質層（iOS 27 語彙的核心）

```
--material-thin   rgba(31,33,37,.72)   + backdrop-filter: blur(28px)
--material-thick  rgba(23,24,27,.86)
```

用於標題列、設定浮層、工具列。半透明 + 背景模糊讓層次關係可感知——你能隱約看到底下有東西，於是「這是一個浮層」不需要文字說明。WebView2 對 `backdrop-filter` 支援完整，這是選擇 WebView2 而非老舊 IE 核心的直接收益。

## 三、排版原則

### 3.1 字級：Major-Third 縮放

```
--fs-micro     10.5px   狀態列、區塊標題（全大寫）
--fs-caption   11.5px   欄位標籤、提示
--fs-body      13px     內容主體
--fs-title     15px     面板標題
--fs-heading   19px     浮層標題
--fs-display   26px     保留
```

桌面生產力工具的內容字級應該是 13px，不是網頁的 16px。資訊密度是專業感的一部分——但密度必須用留白與分組來換取可讀性，不是硬塞。

### 3.2 字距：小字放鬆、大字收緊

```
--ls-micro    0.06em    ← 10.5px 全大寫標題必須放鬆，否則糊成一團
--ls-caption  0.02em
--ls-body     0em
--ls-display  -0.021em  ← 大字收緊才有精緻感
```

這是最容易被忽略、但對「質感」影響最大的一項。

### 3.3 字重：三檔，且 590 不是 600

```
--fw-regular   400
--fw-medium    500   標籤、按鈕
--fw-semibold  590   標題
```

`590` 而非 `600`：在可變字體上，590 比 600 略輕，避免小字級下顯得笨重。這種一階微調正是「原創設計」與「套模板」的差別。

### 3.4 字體堆疊

```css
--font-ui: -apple-system, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI",
           "Inter", "Noto Sans TC", "Microsoft JhengHei UI", system-ui, sans-serif;
--font-num: "SF Mono", "Cascadia Mono", "JetBrains Mono", ui-monospace, "Consolas", monospace;
```

**中文字體明確指定** `Noto Sans TC` → `Microsoft JhengHei UI`，避免落到細明體。

**所有數值一律用等寬字體**（`.num` class）：尺寸、解析度、百分比、計數。理由不只是美觀——數字跳動時等寬字體不會讓版面抖動，這在即時更新的數值旁邊是硬需求。

### 3.5 留白：4pt 網格

```
--sp-1: 4px   --sp-2: 8px   --sp-3: 12px  --sp-4: 16px
--sp-5: 24px  --sp-6: 32px  --sp-7: 48px  --sp-8: 64px
```

不存在 6px、10px、14px。任何間距都必須是這八個值之一。這條紀律靠 code review 維持，也是介面「整齊但說不出為什麼」的來源。

## 四、佈局

### 4.1 三欄式生產力佈局

```
┌──────────────────────────────────────────────────────┐
│ 標題列  Ai Cad │ 文件狀態          │ 匯出 · 設定      │  44px, material-thin
├───────────┬──────────────────────────┬───────────────┤
│           │  工具列                  │               │
│  圖面規格 │ ┌──────────────────────┐ │  引擎與歷程   │
│  （意圖） │ │                      │ │  （檢視器）   │
│           │ │      畫布井          │ │               │
│  296px    │ │                      │ │  312px        │
│           │ └──────────────────────┘ │               │
├───────────┤                          ├───────────────┤
│ 產生圖面  │                          │               │
├───────────┴──────────────────────────┴───────────────┤
│ ● 就緒 · OpenAI              │      檢視模式 · 歷程 3 │  28px 狀態列
└──────────────────────────────────────────────────────┘
```

**為什麼是三欄：** 製圖是「輸入規格 → 看結果 → 調參數」的循環。三欄讓這三件事同時可見，不需要切換頁籤。左欄輸入、中間結果、右欄檢視與微調——這是 CAD、DAW、影像處理軟體共同收斂出的佈局，因為它符合工作流。

**左欄底部固定主動作按鈕**，不隨內容滾動。主要動作永遠在原地，是肌肉記憶的基礎。

### 4.2 設定用浮層 Sheet，不用獨立頁面

設定是「臨時查看與修改」，不是「切換工作場景」。做成獨立頁面會摧毀上下文；做成 Sheet（半透明浮層 + 背景模糊 + 260ms 淡入上浮）讓使用者知道「我還在原本的工作裡，只是暫時掀開一層」。

Sheet 內部再分兩欄：左側引擎清單、右側該引擎的設定表單。避免七個引擎的設定全部堆在一個長捲軸裡。

## 五、元件風格

### 5.1 按鈕：三個變體，語意分明

| 變體 | 用途 | 視覺 |
| --- | --- | --- |
| `primary` | 每個區塊**最多一個**主動作 | 強調色填充，hover 上浮 1px |
| `secondary` | 次要動作（測試連線、儲存） | `bg-raised` + hairline 邊框 |
| `ghost` | 破壞性或可捨棄動作（移除、取消） | 無底、hover 才顯示底色 |

按下時 `translateY(0) scale(0.99)`——**極輕微**的下壓。這是觸覺回饋的視覺替代，過度就變成玩具。

### 5.2 圖示：自繪規範

- 20×20 viewBox，1.5px stroke，`stroke-linecap: round`，`stroke-linejoin: round`
- 一律 `stroke="currentColor"`，`fill="none"`——顏色由文字色繼承，自動適應主題
- 意象**取自製圖語彙**而非通用 UI 語彙：尺寸標註圖示畫的是延伸線與箭頭，選區圖示畫的是虛線框選

### 5.3 表單元素

- 輸入框：`bg-raised`、hairline 邊框、`r-sm` 圓角、focus 時 3px 強調色光環（`--accent-ring`）
- Focus ring **絕不移除**——鍵盤操作是專業工具的基本尊重
- 每個欄位都有 `label` 與可選的 `hint`，hint 說明**為什麼**要填這個、留空會怎樣
- Toggle：36×22px 軌道，`ease-spring` 曲線，滑塊位移 160ms
- Segmented control：滑動的選取指示器，`ease-inout`，取代單選按鈕組

### 5.4 狀態指示：6px 圓點

`idle / ok / warn / danger / busy` 五態。`busy` 帶 1.4s 呼吸動畫（opacity 0.35↔1，非旋轉）。呼吸比旋轉安靜，適合長時間注視的工具。

### 5.5 畫布與選區

- 空狀態顯示**藍圖格線**（24px minor / 120px major），暗示「這是製圖工具」，並在中央寫明下一步操作
- 選區：琥珀色 1.5px 邊框 + 13% 填充 + 左上角編號標籤
- 選區模式下游標變 `crosshair`；拖曳使用 **Pointer Capture**，拖到畫布外也不中斷——這是桌面應用該有的行為
- 小於 1.5% 的框選視為誤點，直接丟棄

## 六、動效原則

```
--ease-out     cubic-bezier(0.22, 1, 0.36, 1)      進場、展開
--ease-inout   cubic-bezier(0.4, 0, 0.2, 1)        位移、變形
--ease-spring  cubic-bezier(0.34, 1.4, 0.64, 1)    僅用於「確認」回饋
--dur-1  90ms   --dur-2  160ms   --dur-3  260ms
```

四條規則：

1. **只有三條曲線、三個時長。** 超出的一律不准。
2. **上限 260ms。** 生產力工具的動畫是「解釋空間關係」，不是表演。超過 260ms 就開始礙事。
3. **只動 `transform` 與 `opacity`。** 保證 60fps，不觸發 layout。
4. **`prefers-reduced-motion` 直接把三個時長歸零。** 無障礙底線，不是選項。

進度條用的是「不確定進度」的無限滑動漸層——因為我們**確實不知道**還要多久。與此同時狀態列顯示具名階段，讓使用者知道現在在做什麼。誠實比假百分比好。

## 七、文案原則

| 不寫 | 寫 |
| --- | --- |
| ✨ AI 智能生成 | 產生圖面 |
| 處理中... | Claude 正在精煉幾何描述 |
| 出錯了！ | 憑證無效 — 請確認 API Key 是否過期 |
| 設定已儲存 ✅ | （不說。設定即時生效，無需通知） |
| 選擇你的 AI 夥伴 | 出圖引擎 |

規則：**動詞明確、主體明確、錯誤附修正建議。** 錯誤訊息一律附 `hint` 說明下一步該做什麼，這是 `ProviderError` 帶 `hint` 欄位的原因。

沉默也是一種設計：成功的操作不需要慶祝，結果本身就是回饋。

## 八、無障礙底線

- 所有互動元素有 `aria-label` 或可見文字
- 選取狀態用 `aria-selected` / `aria-pressed` / `aria-current`，不只靠顏色
- 浮層有 `role="dialog"` + `aria-modal`，**Esc 可關閉**
- Focus ring 永不移除
- 文字對比度 ≥ 4.5:1（深淺主題皆已驗證）
- 尊重 `prefers-reduced-motion` 與 `prefers-color-scheme`
